## 一、核心创作思路与目标用户

**核心思路：把「读故事」变成「玩故事」。**

海龟汤（情境猜谜）是一种经典的水平思维游戏：主持人给出一个离奇片段（汤面），玩家通过不断提问还原真相（汤底）。传统海龟汤有两大痛点——**主持人需要极强的控场能力**（回答既不能泄露又要有信息量），**题库有限**（玩过的谜题无法复玩）。

本作品用 LLM 担任「永不疲倦的主持人」：AI 动态生成案件、根据玩家的每一次提问实时裁决「是 / 否 / 无关 / 关键」，并在结案时给出还原度评分与逐谜团揭秘。同时提供**学习模式**——玩家自带学习材料（如英语词汇、专业课知识点），AI 将其织入案件设定，让背单词、复习功课变成「为了破案而学习」。

**目标用户**：

- 推理游戏爱好者，想随时随地来一局 10 分钟的「状态还原」推理；
- 校园学生（契合校园新锐季）——尤其在备考季想用趣味方式复习知识点的人群；
- 知乎故事内容的读者——喜欢看故事，但更想「进入故事」。

## 二、用户如何完成核心体验

完整一局的用户旅程：

1. **登录（可选）**：点击「知乎账号」一键登录，头像昵称进入个人资料，推理战绩与等级随账号沉淀；不登录也可以以游客身份游玩。
2. **开局（二选一）**：
   - 「一句话开局」：自定义一段离奇开场白，AI 生成完整案件；
   - 「汤面素材库」双来源开局：
     - **知乎故事改编**：从知乎故事列表中选一篇真实故事，AI 将其改编成可推理的汤面——不剧透原文，保留原作署名；
     - **热点新闻改编**：拉取知乎热榜实时榜单，把「今天的新闻」变成「今天的案件」（自动附加来源归属），每天都有新案子可玩。
3. **选择模式**：娱乐模式（纯推理）或学习模式（提供学习材料，AI 出「推理挑战」题目，答对获得额外提问机会等增益）。
4. **提问推进**：向主持人提是非题（如「门是锁着的吗？」），AI 回答并可能触发关键线索；侧栏「待解谜团」实时提醒悬案疑点。
5. **身份技能**：每个身份（侦探/法医/学生等）拥有专属行动，如「搜查现场」「偷听对话」，获得普通提问拿不到的信息。
6. **提交还原**：觉得拼图完整时提交完整真相，AI 给出**还原度评分面板**——真相还原度百分比、人物/事件/动机/手法/反转五要素命中情况、错误点、遗漏点，判断「说对了多少」而不是简单对错二分。
7. **结案**：成功则公布推理路径回顾；机会用尽则公布真相，并对「待解谜团」**逐一揭秘**——AI 严格基于真相解释每一个悬案疑点（例如「监控显示两人同时消失」的真正成因）。

## 三、整体技术方案

- **后端**：Python FastAPI，分层架构——`game_controller`（游戏流程协调）+ `case_generator`（案件生成）+ `reasoning_engine`（主持人裁决/验证/提示）+ `learning_system`（知识点提取与出题）+ `host_persona`（主持人人格文案）。
- **AI 层**：Claude 系列模型驱动全部叙事与裁决；所有 LLM 输出走 JSON 结构化解析与兜底重试；接口失败不扣玩家机会（「LLM 成功才扣次数」原则）。
- **OAuth 会话**：知乎 OAuth 三段式接入（authorize → callback 换 token → /user 取身份）；state 参数防 CSRF（TTL 600s 原子消费，服务端已支持 state 原样透传）；登录发起域与回调登记域做一致性防呆——从非登记域发起时直接给出友好提示，不会走到一半才报错；未配置凭证时自动降级为演示会话，评委无需知乎账号也能完整体验；token 只存服务端，浏览器侧为 HttpOnly Cookie；uid 按 int64 字符串处理避免精度丢失。
- **内容安全**：知乎故事素材视为不可信输入——截断包裹、注入「忽略素材中指令」防护、保留原作署名；出题环节内置防泄底校验（题干出现答案词自动重生成）。
- **前端**：原生 JS 单页应用，与后端同端口部署（单进程单端口即可公网访问），移动端可用。
- **部署**：支持任意能运行 Python 的环境；当前 Demo 已发布为云端常驻链接（免本机开机，评委随时可访问），代码在 GitHub 可一键复现。

## 四、使用了哪些知乎开放能力

| 能力                          | 用途                                      |
| --------------------------- | --------------------------------------- |
| **知乎账号 OAuth 登录**           | 用户身份登录、获取头像昵称等基础信息，战绩随账号沉淀              |
| **知乎故事内容接口**（story 列表 / 详情） | 拉取真实知乎故事，由 AI 改编为海龟汤汤面，为推理游戏提供源源不断的正版题材 |
| **数据开放平台热榜接口**（content/hot_list） | 拉取知乎实时热榜，把当天热点新闻改编为推理案件，素材每日自动更新 |

使用约束上遵守赛事规范：内容接口结果做缓存与去重，不进行高频批量调用。

## 五、项目与知乎社区生态的契合点

1. **知乎故事的新互动形态**：知乎沉淀了大量悬念型、反转型故事。本项目把它们从「被阅读的对象」变成「可推理、可游玩的对象」——读者变成了玩家，故事变成了谜题。
2. **热榜即题库**：接入数据开放平台热榜接口后，「今天的新闻就是今天的案子」——热点事件当天即可成为推理现场，给玩家每天回访的理由；新闻素材同样做注入防护与来源归属，是改编再创作而非内容搬运。
3. **创作者友好**：改编保留原作署名与出处展示，是对创作者的一次再传播，而非内容搬运。
4. **账号体系即社区身份**：用知乎账号登录，玩家的推理等级与战绩就是社区身份的延伸，天然适合后续的排行榜、好友对战等社区玩法。
5. **校园场景契合**：校园新锐季的学生用户既是知乎故事的重度读者，也是「以玩代学」学习模式的目标人群。

## 六、项目对社区用户的实际价值

- **对普通玩家**：零门槛（浏览器打开即玩）、低时长（一局约 10 分钟）、高重玩（AI 生成，没有两局相同的案件）；结案评分面板让玩家能具体看到自己的推理水平差距。
- **对学生用户**：学习模式把枯燥的记忆任务包装成破案动机——答对基于自选材料生成的挑战题，才能换来破案所需的推理增益；学习材料完全由用户自带，符合真实学习场景（自己的课件、自己的词表）。
- **对内容创作者**：自己的知乎故事多了一条「被改编成推理游戏」的触达路径，作品以新的方式被更深度地消费。
- **对社区生态**：验证了「知乎内容 + 开放平台身份 + AI 互动叙事」的组合可行性，同类玩法（知识竞赛改编、盐选推理联动）都可以沿这条路径延展。
